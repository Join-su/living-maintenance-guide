# C1-a15 Pack 약속 v7 — v6에서 요청 선택 칸 셋: 설비 · 알람 시각 · 라인

- 2026-11-03 · 약속 주인 c1a15-pack · 가지 dev-2(지금 시연 길 v5 · v22와 따로) · 근거 D-543 덧 3(지식그래프 범위 '같은 설비' · 예외 조건을 알람 때 보려면 요청 칸이 있어야 함)
- v1 ~ v6은 그대로입니다. 앱 쪽 넘기기는 c1a15-app이 합니다(오케가 이음).

## 바뀐 것(요청만 · 모두 선택 칸)
| 칸 | 꼴 | 어디서 | Pack이 쓰는 곳 |
|---|---|---|---|
| `equipment_id` | 문자열(영문 · 숫자 · `-` 1 ~ 40자) — 앱 이력 `equipment_id`와 같은 꼴(예 `M-02`) | start · judge | 그래프 질의 범위 '같은 설비'(옵션 scope = equipment) |
| `occurred_at` | 시간대 붙은 ISO 8601 · 초까지(예 `2026-11-03T21:15:00+09:00`) | start · judge | 이 시각 **앞선** 기록만 근거 · 최근 기록 무게(반감 일)의 기준 시각 |
| `line_id` | 문자열(같은 꼴) | start · judge | 받기만 함 — 같은 라인 조건(⑥ 예외 기록이 만드는 조건 붙은 관계)에 쓸 자리. 지금 판정은 읽지 않음 |

- 칸이 없으면 판정은 v6과 같습니다.
  - scope = equipment인데 `equipment_id`가 없으면 같은 증상군 범위로 셉니다. 고른 기록 조각의 `graph.scope`에 실제로 쓴 범위를 남깁니다.
  - `occurred_at`이 없으면 기준 시각은 이력 마지막 기록 시각입니다(지금과 같음).
- 같은 증상군 안에서만 '같은 설비'를 봅니다. 다른 증상군의 기록은 그 원인 후보가 아니기 때문입니다.

## 예시
- v6 예시 그대로(바이트 같음): 요청 넷 · judge · report · start · 알람 결과 셋
- 새로 하나: `start-context.request.json` = `start.request.json` + 세 칸

## 바뀌지 않는 것
- 결과 schema(run_result.json)는 v6과 바이트가 같습니다.
- 요청의 그 밖 칸 · 거절 규칙(사용자 ID · 메모 원문 · 정정 사유 자유 글 0)도 같습니다. 모르는 칸은 v6처럼 거절합니다.
