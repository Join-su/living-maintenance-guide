## 세 방식
1. **매뉴얼만** — 냉각 장 14절 전부(점검 → 조치 → 호출, 각 안은 소요 분 순)
2. **유사도(지금 꼴)** — packrt 0.15.0 `FlatLocal.search2` 그대로(BM25 + 센서 7칸 재정렬 0.5/0.5 · 상위 10)
   - 원인 몫은 지금 Pack R4(α 0.5 + 점수 합)와 같습니다.
   - **지금과 다른 점:** 벡터 순위는 없습니다(질의 임베딩 = provider 호출).
   - **2′**는 재정렬 범위를 전체로 넓힌 것입니다(옵션 rerank.pool). 센서가 전체 이력에서 고릅니다.
3. **관계 질의 노드(D-533)** — 아래 'D-533 설계'.
3(옛). **관계 셈(D-531)** — 그때까지의 이력에서 셉니다.
   - 셈: 같은 라인 30분 안 동시 · 같은 설비 3일 안 부품 교체 · 같은 설비 14 ~ 21일 전 필터 늦은 교체 · 센서 모순.
   - 참인 관계가 있으면, 지난 기록 중 그 관계가 참이던 기록의 원인 분포를 씁니다(5건 이상일 때 · 가장 한쪽으로 쏠린 관계 하나).
   - 없으면 같은 계절 원인 분포를 씁니다.
- 2 · 3의 '원인 몫 → 불러올 단계'는 같은 규칙(`select`)입니다.
  - 매뉴얼 밖 원인 몫이 0.5 이상이면 호출 · 인계만 불러옵니다.
  - 아니면 몫 0.2 이상인 원인의 점검 · 조치를 불러옵니다.
  - 순서는 몫 ÷ 소요 분입니다.

## D-533 설계(방식 3)
- **노드 하나 = 관계 질의**(알람 실행 안 · 지금 이력 리트리버 자리). 옵션은 셋, 일반적인 것만입니다(`node.yaml`).
  - `scope` 근거 범위: 같은 설비 · 같은 라인 · 같은 기종(이 가상 공장은 30대가 한 기종이라 = 공장 전체)
  - `half_life_days` 최근 기록 무게(며칠마다 반 · null = 같은 무게)
  - `min_support` 최소 근거 수(모자라면 매뉴얼 순서)
  - 기본값(plant · null · 3)은 이력 안 사례(dev)로만 골랐습니다.
- **예외 = 규칙 표**(`exceptions.csv`). 한 줄이 예외 하나이고, 위 줄부터 봅니다.
  - 알람에서 조건이 참이면, 범위 안 지난 기록 중 같은 조건이 참이던 기록(근거)을 셉니다.
  - 근거가 min_support 이상이고 근거의 1등 원인이 그 줄 결론과 같으면, 근거의 원인 몫을 씁니다('분포'는 1등 확인 없이).
  - 새 예외는 한 줄 더함입니다. 있는 관계(`self` · `same_line` · `machine_work`)와 칸만 쓰면 노드 · 옵션 · 관계 층은 그대로입니다.
- **적재 두 층**
  - 원본 층 = `data/history.jsonl`(승인된 보고서 칸) · `data/occurrences.jsonl`(알람). 고치지 않습니다.
  - 관계 층 = `layer/<버전>/`. `build_layer.py`가 원본 + `relation_defs.yaml`로 다시 만듭니다(같은 바이트). 규칙은 굽지 않습니다.
  - 노드는 manifest의 원본 sha256이 지금 원본과 다르면 멈춥니다.
- **바뀐 것별 처리**
  1. 질의 옵션 → 적재 그대로
  2. 규칙 숫자 → 적재 그대로(`exceptions.csv`만)
  3. 관계 정의 → 관계 층만 새 버전 → 같은 시험 → `node.yaml` layer 줄로 바꿔 끼움 · 옛 버전은 되돌림용으로 남김(`demo_redefine.py`)
  4. 틀에 새 칸 → 원본에 있으면 다시 만들 때 채움 · 없으면 옛 기록 빈칸
