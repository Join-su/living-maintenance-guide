1Docker Desktop 설치 브라우저

할 일
  1. Docker 공식 내려받기 쪽에서 내 컴퓨터(Mac Apple 칩 · Mac Intel · Windows)에 맞는 설치 파일을 받아 설치
  2. Windows는 설치 중 Use WSL 2를 켠 채로 둠
  3. 설치 뒤 Docker Desktop을 열고 왼쪽 아래가 초록(Engine running)이 될 때까지 기다림
보일 것
Docker Desktop 첫 화면 · 왼쪽 아래 초록 글 Engine running
막히면
Windows에서 WSL 오류 → 관리자 PowerShell에서 wsl --install 뒤 다시 시작
알아 둘 것
리눅스 서버(AWS)는 1 · 2번을 건너뜁니다 — 문서 11 상자 1 · 2(3 · 4번).
[그림: Docker Desktop 첫 화면]빨간 테: 왼쪽 아래 Engine running

2메모리 늘리기 Docker Desktop

할 일
  1. 오른쪽 위 톱니 Settings → Resources → Memory를 8GB 이상(16GB 권장)으로
  2. Apply & restart
보일 것
Memory 값이 바뀌고 Docker가 다시 초록이 됨
막히면
Windows(WSL)는 이 칸이 없음 → 사용자 폴더의 .wslconfig에 memory=8GB 줄 확인 필요 · Windows 화면 · 줄 확인
[그림: Settings → Resources 화면]빨간 테: Memory 막대 · Apply & restart

3저장소 받기 터미널

할 일
  1. 터미널(Windows는 PowerShell)을 열고 아래 두 줄
git clone <이 저장소 주소>
cd living-maintenance-guide
보일 것
폴더 안에 docker-compose.yml · .env.example · services · docs가 보임
막히면
'git: command not found'(리눅스 서버) → 문서 11 상자 2(4번)

4.env 만들기 — 키와 비밀번호 넣는 곳 터미널 · 편집기

할 일
  1. 견본을 복사
  2. 편집기로 .env를 열어 OPENAI_API_KEY= 뒤에 내 키를 붙여 넣음
  3. JEV_BASE_URL= · JEV_API_KEY= 뒤에 Jev 주소 · 키(효율 개선 08에 필요)
  4. change-me로 시작하는 비밀번호 줄 여섯을 아무 긴 글자로 바꿈(처음 켤 때 이 값으로 DB가 만들어짐)
  5. 다른 프로그램이 이미 8081 · 8082 · 8796 · 28576 · 28789 · 18868을 쓰면 포트 줄만 바꿈 — 같은 컴퓨터에 두 벌을 띄울 때는 COMPOSE_PROJECT_NAME=도 다른 이름으로(문서 09 3번)
cp .env.example .env
보일 것
.env 한 파일 · git에는 올라가지 않음(.gitignore)
막히면
비밀번호를 나중에 바꾸면 DB가 안 열림 → 문서 09의 '처음부터 다시'
알아 둘 것
필요한 열쇠 둘: OpenAI(필수 · 모든 실제 Run) · Jev(효율 개선 ⑤ 품질 검토 — 예/아니오로만 답하는 작은 판정 모델 · 주소와 키는 팀 안내). Jev가 없으면 정확도(07)와 효율 ①은 끝까지 가지만, 출력이 바뀐 후보(효율 ②)는 ⑤에서 decide_no_key_file로 멈춥니다(시작 로그 'agentops: Jev 키 없음 — …'). Jev 열쇠를 넣거나, .env에 LLMOPS_AUTO_REVIEW=off(품질 검토 없이 비교 · 채택 · 개선 기록에 품질 검토 꺼짐이 남음). 키가 보이는 화면이라 이 단계는 그림이 없습니다.

5모두 띄우기 터미널

할 일
  1. 아래 한 줄 · 처음에는 이미지를 만들어서 오래 걸림 확인 필요 · 첫 실행 시간 어림
docker compose up -d
보일 것
끝에 Started · Healthy 줄들 · 오류 없이 프롬프트로 돌아옴
막히면
compose up이 'NEO4J_AUTH 필요 — .env를 만드세요'로 멈춤 → .env가 없거나 그 줄이 빔(4번) · 다 떴는데 pack-server만 자꾸 다시 켜짐 → docker compose logs pack-server --tail 20에 'OPENAI_API_KEY 없음 — .env에 키를 넣으세요' → 4번 키 줄 · 메모리 부족으로 멈춤 → 2번 · 그 밖은 문서 10
[그림: 터미널 — compose up 끝 화면]

6정상인지 확인 터미널 · 브라우저

할 일
  1. 상태 보기 — 한 번 돌고 끝나는 넷(app-init · app-examples · kg-init · trace-db-init)은 Exited (0)이 정상, 나머지는 running(healthy가 붙지 않는 것도 있음)
  2. 배포 서버는 켜진 뒤 길게는 5분까지 준비함 — health가 healthy가 될 때까지 기다림
  3. 브라우저로 정비자 http://127.0.0.1:8081 · 상급자 http://127.0.0.1:8082 · AgentOps http://127.0.0.1:18868
docker compose ps
curl -s http://127.0.0.1:8796/health
보일 것
세 화면이 열림 · AgentOps는 'Project가 없습니다'(빈 상태가 정상) · health 응답 '{"status":"ok", …}' 한 줄
막히면
한 컨테이너가 Exited (1) · Restarting → docker compose logs <이름> --tail 50으로 끝 줄을 보고 문서 10
[그림: docker compose ps 결과 + 세 브라우저 창]빨간 테: Exited (0) 네 줄 · AgentOps 빈 화면

7끄기 · 다시 켜기 터미널

할 일
  1. 끄기(자료는 남음)
  2. 다시 켜기 — 두 번째부터는 빠름(1분 안팎)

docker compose up -d

docker compose down -v는 자료까지 모두 지웁니다. 처음부터 다시 할 때만 씁니다(문서 09).
