살아있는 정비 길잡이 · 저장소 안내길잡이

저장소 안내 — 처음부터 따라 하기

정비자 앱 · 상급자 앱 · 지식 그래프 · 배포 서버 · AgentOps를 한 컴퓨터에서 도커로 띄우고, 빈 AgentOps에서 프로젝트를 만들어 운영 서버와 잇고, 메인 · 정확도 · 효율 시연까지 그림을 보며 따라 합니다.

필요한 것
  • Docker Desktop · 메모리 16GB 권장(최소 8GB) · 디스크 20GB(AWS 서버는 문서 11 — 8GB · 30GB)
  • 열쇠 둘 — OpenAI API 키(쓴 만큼 요금) · Jev 키(효율 개선 품질 검토)
  • git · 브라우저

처음 띄우기

  1. 02 도커 올리기 — Docker Desktop을 깔고, 저장소를 받아 키 · 비밀번호를 넣은 뒤 한 줄로 모두 띄웁니다. 끄고 다시 켜는 법까지.
  2. 03 DB 적용 — 처음 켤 때 저절로 되는 DB 준비(표 만들기 · 시드 채우기)를 눈으로 확인하고, 처음 상태로 되돌리는 법을 봅니다.

AgentOps

  1. 04 AgentOps 프로젝트 만들기 · 운영 서버와 잇기 — 빈 AgentOps에서 프로젝트를 만들고, Pack을 버전으로 등록하고, 시험 묶음을 올려 첫 평가를 돌린 뒤, 운영 지정과 배포 서버 연동까지 합니다.

앱 · 시연

  1. 05 정비자 앱 · 상급자 앱 쓰기 — 알람을 받고 점검 · 조치 · 보고서를 쓰는 정비자 앱과, 보고서를 확인 · 승인하는 상급자 앱의 기본 쓰임을 봅니다.
  2. 06 시연 — 메인 — 알람 하나가 정비자 점검 → 보고서 → 상급자 승인 → 지식 그래프 반영 → AgentOps 새 버전까지 이어지는 것을 한 번에 봅니다.
  3. 07 시연 — 정확도 개선 — 헛걸음 한 번이 기록 · 승인 · 그래프 반영 · 자동 개선 · 배포를 거쳐 같은 알람의 첫 점검을 바꾸는 것을 봅니다. 되돌리면 다시 원래대로.
  4. 08 시연 — 효율 개선 — 정확도는 그대로 두고 비용 · 토큰 · 속도를 줄이는 개선 두 가지(① 보조 단계 모델 바꾸기 ② 같은 보고서를 두 번 쓰는 단계 빼기)를 같은 시험으로 비교하고 배포합니다.

다시 하기 · 막힐 때

  1. 09 초기화 · 첫 상태 — 시연을 여러 번 해도 같은 출발에서 다시 시작하는 법과, 모두 처음부터 다시 만드는 법을 봅니다.
  2. 10 막히면 · 자주 묻는 것 — 자주 막히는 곳과 할 일을 표로 모았습니다. 표에 없으면 해당 컨테이너의 끝 로그 50줄을 함께 남겨 주세요.

서버에 올리기

  1. 11 AWS 서버에 올리기 — 같은 저장소를 AWS 리눅스 서버(EC2)에 받아 도커로 띄우고, 내 컴퓨터 브라우저에서 SSH 터널로 화면을 봅니다. 서버는 밖으로 22번(SSH)만 엽니다.
